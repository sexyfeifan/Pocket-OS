# Pocket OS — 智能自媒体操作系统

面向内容创作者的全生命周期排期管理系统。每个节点独立安排日期，支持并行工序。Canbox 仅导入真实拍摄日期，不推算其他节点。

## 功能特性

- **手动排期优先**：修改发布日期、工序顺序或新增工序时，不会擅自改动其他日期
- **独立排期**：已移除倒排、顺推和碰撞推挤；拖动、缩放或修改节点只影响当前节点
- **直接编辑**：打开项目即可改名称、日期、完成状态，无须切换编辑模式
- **撤销与历史**：当前页面有 30 次撤销；另外服务器保存最近 30 次已保存排期变更，刷新后仍可逐节点预览恢复
- **Canbox 集成**：从罐头场通告排期系统拉取拍摄安排，一键导入或反向绑定
- **甘特图日历**：无缝横向滚动，合并相邻工序色块，拖拽调整时间
- **选题卡编辑**：工序时间段选择、前置准备、分类标签、进度追踪
- **冲突预警**：工序过期未完成时红字警告
- **工序设置**：自定义标准制作流程，拖拽排序，颜色选择
- **数据持久化**：Docker Volume 挂载，JSON 文件存储

## 快速开始

### Docker Compose（推荐）

要测试当前仓库里的 v1.9.7 源码，可先在项目目录构建本地镜像：

```bash
docker build -t pocket-os:1.9.7 .
docker run -d -p 8080:8080 --name pocket-os-197 \
  -v pocket-os-data:/app/data \
  pocket-os:1.9.7
```

下面的 `latest` 示例适用于镜像发布后部署：

创建 `docker-compose.yml`：

```yaml
services:
  pocket-os:
    image: sexyfeifan/pocket-os:latest
    environment:
      POCKET_OS_PASSWORD: ${POCKET_OS_PASSWORD:-}
      POCKET_OS_VIEW_PASSWORD: ${POCKET_OS_VIEW_PASSWORD:-}
    ports:
      - "8080:8080"
    volumes:
      - pocket-data:/app/data
    restart: unless-stopped

volumes:
  pocket-data:
```

启动：

```bash
docker compose up -d

# 打开 http://localhost:8080
```

## Canbox 通告集成

Pocket OS 支持从通告排期系统自动拉取拍摄安排。

1. 在排期系统后台启用外部 API
2. 在 Pocket OS 侧边栏点击「从拍摄通告导入」
3. 输入排期系统地址
4. 选择要导入的项目，只填写通告拍摄段，其余工序日期留空

支持：
- 按时间轴浏览，自动定位到今天
- 导入时自动关联拍摄地、导演、摄影等信息
- 不连续拍摄日期会保留为多个独立拍摄段
- 选题卡可反向绑定通告排期

## 标准制作流程

| 工序 | 说明 | 新建时日期 |
|------|------|----------|
| 脚本 | 文案撰写 | 未安排 |
| 拍摄 | 实际拍摄，可分段 | 未安排；通告导入时填写拍摄日期 |
| ACO | 粗剪版本 | 未安排 |
| BCO | 精剪版本 | 未安排 |
| 发布 | 最终发布 | 与项目发布日期一致 |

可在「工序设置」中自定义新项目的工序名称、颜色、顺序。现有项目的工序可直接改名、增删和排序，设置变化不会改动现有日期。

## 日常操作

1. 点击「新建选题」后直接输入名称；所有节点默认未安排。
2. 直接选择节点的开始、结束日期；同日工序只需选择一天。前移/后移一天会整体移动当前节点并保持时长。
3. 点击时间轴色块进入对应节点编辑；点击时间轴空格或项目月历日期安排节点、添加备注。
4. 拍摄可添加多个独立段；拖动一个拍摄色块只移动该段，节点的前移/后移按钮则移动整组拍摄段。
5. TML 先预览再应用，只更新列出的节点。可显式选择年份；过去月份不会自动猜成明年。
6. 修改自动保存；查看「已保存」提示后即可刷新。连续编辑按顺序保存，失败会重试；同步冲突由用户选择版本。

升级不会自动重排既有项目。此前被错误移动的日期需要根据实际安排手动校正。

## 技术栈

- **前端**：Vanilla JS + Tailwind CSS（CDN）
- **后端**：Node.js + Express
- **存储**：JSON 文件
- **部署**：Docker (Node.js 22 Alpine)，镜像约 45MB

## 工作台与只读看板（v1.9.7）

- 工作台：`/`；只读入口：`/view`，旧 `/canbox` 地址兼容。
- 看板包含工作概览、项目卡片、周/月日历、全景时间轴与只读详情。只有查看、搜索、筛选和全屏操作；无编辑、删除、勾选完成或拖拽改期功能。
- 看板通过独立只读 API 和 SSE 获取服务器已保存的数据，不读取管理设置、密钥、导入原文和历史快照。失败时保留旧画面并显示断线提示。
- 项目状态（筹备、制作中、待反馈、已完成）与排期状态独立。点击“确认当前排期”只确认已安排的日期；改期会撤回确认，不会重排。
- 新建可选口播、商业拍摄、短视频模板，也可把现有工序结构保存为模板。复制项目默认清空日期、完成状态、备注和通告绑定。
- 紧凑排期开关不改变数据；从卡片进入再返回会保留视图和筛选。
- TML 预览支持逐节点、逐备注勾选；通告日期应用/绑定先比较前后日期。预览后排期变化必须重新预览。
- 历史从本版开始记录，最多保留 30 次**已保存**的日期/节点增删变更（连续编辑可能合并为一次保存），不是备份替代品。恢复只应用选中的节点，保留已有节点的名称、完成状态和其他项目字段。

### 对外只读分享

未设置密码时仍兼容原来的本地部署，但这**不是权限隔离**：知道服务地址的人仍能访问工作台。不要将无密码实例直接暴露到公网。

在 Compose 所在目录的本地 `.env` 中设置两个不同的强密码，然后重新创建容器：

```dotenv
POCKET_OS_PASSWORD=替换为独立的管理密码
POCKET_OS_VIEW_PASSWORD=替换为不同的查看密码
```

```bash
docker compose up -d pocket-os
```

只分享 `/view` 地址与查看密码，不分享管理密码。浏览器登录用户名可任意填写，权限由密码区分；测试查看身份请使用无痕窗口或另一浏览器，避免复用已缓存的管理登录。公网访问必须通过 HTTPS。查看密码能够查看全部项目的看板字段（含准备事项和日期备注），本版没有按客户/项目分别授权。修改查看密码并重建容器即可撤销旧密码；已被读取或下载的内容无法收回。

只设置查看密码、未设置管理密码，或两者相同，服务器会拒绝启动。管理端侧栏显示当前访问保护状态。

## 环境变量

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `PORT` | `8080` | 服务端口 |
| `POCKET_OS_DATA_DIR` | `/app/data` | 自定义数据目录（测试或非 Docker 部署） |
| `POCKET_OS_PASSWORD` | 空 | 管理密码；公网部署必须设置并使用 HTTPS |
| `POCKET_OS_VIEW_PASSWORD` | 空 | 独立查看密码；要求同时设置不同的管理密码 |

## 数据备份

数据存储在容器内 `/app/data/app_state.json` 和 `/app/data/topics/*.json`，通过 Docker Volume 映射到宿主机。

| 场景 | 数据安全 |
|------|----------|
| 重启容器 | ✅ |
| 删除容器 | ✅（数据在 Volume 中） |
| 升级镜像 | ✅ |
| 换设备访问 | ✅（同局域网） |

也可在界面中使用「导出备份」功能下载 JSON 文件。「导入恢复」会完整替换服务器上的现有选题，操作前会二次确认。
